# Internals use the Rust ecosystem instead of mirroring v9

The HTTP API, environment variables and storage layout stay what v9 offered. How the server implements them no longer follows the TypeScript server: each piece uses the crate the Rust ecosystem settled on.

- Migrations run on `sea-orm-migration` from one frozen baseline, the schema v9.10 left. A database still carrying Kysely's bookkeeping is taken over on startup: with all nine v9.10 migrations recorded it is adopted with its data, anything older is dropped and recreated and storage is cleared with it. Kysely tables a v9 replica recreates beside an already migrated database are simply removed. Migrations keep Kysely's advisory locks, so such a replica waits instead of racing. Neither needs operator input, and a cache can afford losing data that old. The two implementations can no longer share a database.
- Configuration is a `clap` parser; every variable doubles as a flag and `--help` lists them. An empty variable counts as unset.
- The Twirp `CacheService` is generated by `twirp-build` and `pbjson` from `proto/cache.proto`, compiled by `protox` so building needs no `protoc`. Errors use Twirp's standard `{code, msg}` body.
- Management API query strings are parsed by `serde_qs` into typed structs; `Range` headers by `http-range-header`, which adds suffix ranges.
- Cleanup schedules are `tokio` intervals that run once at startup and then every period, not aligned to local wall-clock time.

Superseded parts of earlier decisions:

- ADR-0010: the Kysely bookkeeping tables and migration names are gone, so a database is no longer readable by both implementations.
