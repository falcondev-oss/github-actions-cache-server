# Atomically visible uploads replace merge promotion

Every storage adapter's `uploadStream` guarantees atomic visibility: an object never exists partially, and overwriting an object never disturbs active readers of the previous version. Object stores provide this natively (multipart and resumable uploads only appear on completion); the filesystem adapter writes to a top-level temp entry and renames it into place, leaving crash debris as Orphaned Storage for reconciliation per ADR-0001. The Merge therefore writes directly to its final object with no intermediate candidate-and-promote step: because Parts are immutable, a merger that lost its Merge Lease can only overwrite the merged object with identical bytes, so the lease fence only guards which worker marks the Merge complete. The rejected alternative — uploading to a candidate object and promoting it under the lease — required a server-side copy that S3 caps at 5 GiB and pinned a database transaction across the copy.
