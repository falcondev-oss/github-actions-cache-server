# Database records authorize retained storage

The database is authoritative when it disagrees with physical storage. The configured filesystem root or `gh-actions-cache/` object-store prefix is wholly owned by the server. Database state changes are committed before their corresponding physical deletions; a failed physical deletion therefore creates Orphaned Storage for reconciliation instead of leaving a Cache Entry that points to missing data. Stored cache data that is referenced by neither an upload nor a storage location may be deleted once its newest object is at least 24 hours old; the grace period has a dedicated setting with a 24-hour default. Consequently, restoring an older database while retaining newer physical storage can delete data unknown to that database. This favors bounded storage use and automatic recovery from interrupted cleanup over preserving untracked data indefinitely.
